# Data access and security terms (draft)

> Draft version 2026-10-18.1, written with AI assistance. It must be reviewed and approved by an administrator,
> with legal advice where needed, before any production release. Until then use only test or local databases.

By adding a database connection to the ESI assistant you confirm and agree to the following.

## 1. Your authority
You are authorized by the owner of the database to connect to it, to read its structure and data, and to let this
application do so on your behalf. You are responsible for complying with the laws, contracts and internal policies
that apply to the data, including data-protection law.

## 2. What the application stores
- The connection string, encrypted at rest. It is decrypted only inside the core service at the moment of use and is
  never shown to you again, sent to your browser, sent to the AI service, or written to logs.
- Your chat questions, generated SQL and scripts, saved visualizations and dashboards, linked to you and to this
  connection. Visualizations store column names only, never row data.
- An application log of each query you run (time, duration, outcome and the statement with literal values masked).
  Query results are not stored.

## 3. What the application does with the database
- It reads schema metadata (tables, views, columns, keys and stored procedure definitions).
- It runs only single, read-only SELECT statements, and only when you explicitly ask it to. Statements are checked
  before they run; writes, schema changes and procedure calls are refused. Stored procedures are never executed or
  created; generated procedures are scripts for you to review and run yourself.
- We strongly recommend connecting with a database login that has read-only permissions.

## 4. What the AI service receives
The AI service receives your question, the schema metadata and, for visualizations, column names and types. It
does not receive row values or connection strings.

## 5. Withdrawing consent
You can withdraw consent for a connection at any time. Withdrawal immediately disables everything for that database
(schema, chat, queries, scripts, saved visualizations and dashboards) and hides the related data without deleting
it. Granting consent again restores access. Deleting a connection removes the encrypted connection string.

## 6. Changes to these terms
If these terms change, you must accept the new version before your connections can be used again.
